# D题——山区洪涝灾害下无人机运输与通信协同优化

本仓库 `td6dz4hs7j-sys/modeling` 承载项目标识 `D-UAV-guobaotegong` 的三人协作框架。

当前阶段：项目初始化。此提交只建立协作边界、目录和记录模板，不开始解题，不写入模型结论、实验数据或虚构参考文献。

## 目录用途

| 目录 | 用途 | 约束 |
| --- | --- | --- |
| `data/` | 题目附件、原始数据和经确认的数据接口 | 原始附件只读；来源、版本和校验信息待登记 |
| `src/` | Python / MATLAB 源码、配置和可复现脚本 | 只提交可审阅的源码与必要配置 |
| `results/` | 正式运行产生的结果表、复现清单和验证记录 | 不提交未经实际运行验证的结果 |
| `figures/` | 数据图、过程图、结果图和流程图 | 图表必须能追溯到真实输入和运行记录 |
| `paper/` | 论文草稿、模板副本和导出产物 | 目标竞赛当届规则和模板待核验 |
| `docs/` | 进度、模型参数、分工和交接记录 | 公共接口变更需在 PR 中说明影响 |

根目录的 `使用指南.md` 是已安装 math-modeling skill 的使用边界说明；`SKILL_VERSION.md` 固定本项目采用的 skill 版本和源 commit。

## 项目运行方式

当前尚未确定主入口、数据文件名、求解器和环境版本，因此运行命令统一标为待补充：

- Python：`待补充：确定 Python 版本、依赖文件和主入口后填写。`
- MATLAB：`待补充：确定 MATLAB 版本、主脚本和工具箱后填写。`
- 复现：`待补充：在模型和参数冻结后填写唯一复现命令。`

在运行方式确认前，不要自行猜测入口脚本、参数、数据格式或输出结论。

## 三人协作步骤

1. 开始任务前，先读取 `docs/项目进度.md`、`docs/模型与参数.md`、`docs/分工.md`，再检查 `git status` 和当前分支。
2. 从最新 `main` 创建独立任务分支，建议命名为 `feat/<成员>-<任务>`、`fix/<成员>-<任务>` 或 `docs/<成员>-<任务>`。
3. 每个任务只修改自己负责的文件；需要改公共模型、参数或数据接口时，先在 PR 描述中说明影响范围。
4. 完成后运行与任务相称的检查，把改动、验证结果、未解决问题和下一步写入对应交接记录，再提交 PR 到 `main`。
5. 由团队成员评审 PR 后人工合并；本仓库不自动合并 PR，也不强制推送。

详细约束见 `AGENTS.md`。项目内容仅供学习和研究参考，正式参赛前须由队伍人工核对并以当届官方规则为准。
